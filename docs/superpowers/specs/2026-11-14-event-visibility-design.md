# Free events and Private/Public events: design (app tasks 4 and 5)

Nov 14, 2026 · Status: written from decisions in `docs/decisions/2026-11-10-fiuu-and-pending.md`; waiting for the owner to read it. No code written.

## Goal

1. A free event is a listing: guests can Save it, get Directions and open the source link, but cannot Join. The host sees how many people saved it.
2. A host chooses **Public** or **Private** for each event. Private events are hidden from every list and open to anyone who has the link.

## Decided (from the owner)

- Free events: Save-only, with a saves count for the host (reverses "free events need only a sign-in to join").
- Private: anyone with the link can open the event, join and pay; they can forward the link; no host approval per guest.
- Private events never appear in Explore, View all, search, the map, or the host's public profile.

## Defaults I chose

- "Free" means `price_sen = 0` or `accept_bookings = false`, the same rule the app already uses to pick the free event page.
- Visibility can be changed at any time, also after guests booked. Making an event private only hides it from lists; guests who already booked keep their tickets.
- Every event gets a short random `share_code` (10 characters, letters and digits) when it is created. Links use the code, not the id. A public event can also still be opened by id inside the app.
- A guest who opened a private event by link may Save it; the Saved list then shows it.

## Free events

Database:
- `bookings.create_booking` refuses free events (`free_event_no_booking`). Existing `confirmed` free bookings stay valid and visible in Tickets.
- `identity.saves_count(p_event_id)`: returns the number of saved rows, only for the event's host.
- `events.host_events` and `events.host_page` return `saves` for free events.
- Seat counts, capacity and "N spots left" are not shown for free events.

App:
- Free event page: "Free" label, when, area and distance, description, Directions, source card, Save heart. No Join button, no checkout, no ticket. The line "Join to get your ticket" is removed.
- Host event card and details show "N saves" for free events instead of joined, checked in and gross; Scan tickets and Guest list are hidden for them.
- Replace the free-join e2e journey with a free-save journey.

## Private and Public events

Database (`events` module):
- `events.events` gets `visibility text not null default 'public' check (visibility in ('public','private'))` and `share_code text not null unique` (generated by a default function; backfilled for existing rows).
- The open read policy `events_public` becomes `status in ('published','ended') and visibility = 'public'`. The host still reads all their own rows through `events_own`.
- `events.event_by_code(p_code text)` (`security definer`, callable by anon and authenticated): returns the event detail for a published or ended event of either visibility; the only way to read a private event you do not own.
- Every function that lists events (`events.feed`, `events.list_all`, search, map, `host_page` "Coming up", `event_counts` lists) filters `visibility = 'public'`.
- Functions that show an event to someone who already has it must still work for private events: `bookings.my_bookings`, `bookings.booking_brief`, the chat event card, `identity.saved` list, reviews, notifications. Each gets a test with a private event.
- `identity.toggle_save` and `bookings.create_booking` accept a private event by id (the id is only learned through the code or a booking).
- `events.update_event` and `events.save_draft` accept `visibility`; it is not one of the fields locked after guests join.

App:
- Event form (and Edit event): a **Public / Private** switch with the text "Private events are hidden from Explore and search. Only people with your link can open them." Default Public.
- Host event details: a **Share** card with the link, Copy and the system share sheet (see the sharing spec).
- Event page: a "Private event" tag when the event is private.
- Deep link `/e/:code` resolves through `events.event_by_code` (see the sharing spec).

## Tests (written first)

pgTAP: anon and other users cannot read a private event by table or by feed; `event_by_code` returns it; the host reads it; private events missing from `feed`, `list_all`, search, map and `host_page`; a guest with a booking still sees it in `my_bookings`; save a private event and see it in Saved; changing visibility after guests joined; `create_booking` refuses a free event; `saves_count` is host-only and counts correctly; share codes are unique and backfilled.
Flutter: free event page has no Join and shows Save and Directions; host sees "N saves"; visibility switch in the form and the edit screen; private tag on the event page; free-save journey; existing tests that expected "Join · Free" are updated.
Device checks: iOS first, then Android.

## Out of scope

Host approval of individual guests; passwords or codes on private events; changing the lock rules for date, place, price and refund window.
